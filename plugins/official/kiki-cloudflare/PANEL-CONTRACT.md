# Cloudflare panel contract

Panel id `cloudflare`; page `./panel.html`; slot `sidebar` keeps this App service's management available without a workspace or session, including when workspace plugin-use filtering is enabled. Use the existing Kiki panel bridge and settings/prerequisite installation UI. This package requires the separate App-lifecycle Host candidate; do not publish it against an unchanged Host. The private candidate registers `plugin_app_lifecycle` (default off), enabled in development with `KIKI_EXPERIMENTAL_PLUGIN_APP_LIFECYCLE=1`. Release integration must make the capability available by default, publish the matching SDK, and add the package to the catalog; the experimental switch is not a permanent user step.

## Intended path

Install and enable the plugin → install cloudflared if missing (existing prerequisite button) → **Create tunnel in Cloudflare** opens the official dashboard (create a tunnel, configure its published hostname and origin service there), then paste its connector token → **Save and connect**. Already configured users can paste a token directly or reuse a certificate and select their tunnel. The dashboard owns resource creation, DNS/public routing, plan choices and billing; the plugin does not recreate its cloud console. Default `autoStart=true`: a configured tunnel starts with Kiki. **Stop** pauses this Kiki run only. **Start with Kiki** is a persistent preference, independent of whether it is running now. Changing that preference must not silently stop a running tunnel.

A remote token needs no browser login. **Browser login** runs official `cloudflared tunnel login`; it generates an account-wide `cert.pem`, not a Wrangler OAuth credential. Existing certificates are reused, not overwritten. `apiToken` is optional account API authentication for account/tunnel discovery, separate from `tunnelToken`; never imply that a tunnel token can deploy Workers/Pages.

## Backend

Generic GUI bridge: `{channel:'kiki.panel.v1',kind:'request',id,method:'plugin.call',action,args}` works without a session. `{...,method:'plugin.openExternal',url}` opens a normal HTTP(S) webpage through the existing Kiki host adapter (reject other protocols); no plugin-specific domain declaration. Session summary/message methods still require a real session. Install uses `{...,method:'plugin.installPrerequisite',prerequisiteId:'cloudflared',consent:true}`; the button is the explicit download consent, not a second confirmation. Responses retain the existing `{kind:'response',id,ok,result?,error?}` envelope.

`setup {}` returns `{url:'https://dash.cloudflare.com/?to=/:account/tunnels',docsUrl:'https://developers.cloudflare.com/tunnel/get-started/',managedExternally:true}`. Open `url` via `plugin.openExternal`; keep only a short instruction next to the token field. Resource creation is a real official product path, not mocked creation in development tests.

`handlePanelRequest(action, args, context)` returns the current status for all lifecycle actions, or `{items}` for discovery. Errors throw a safe actionable message (no token or raw process log). Host passes persisted settings, `userHome`, `dataDir`, and `updateSettings(values)`; configure is one backend action which validates, saves via existing Host settings, applies, and connects. No browser keepalive is needed.

- `status {}`: no outbound Cloudflare requests; dependency probe is cached. Return `{schemaVersion:1, dependency:{state:'ready'|'missing'|'error',version?,path,installable:boolean}, account:{certificate:boolean,apiToken:boolean}, configuration:{mode:'token'|'local',tunnelId,configPath,tokenFile,credentialsFile,certificatePath,cloudflaredPath,accountId,publicUrl,autoStart,tokenConfigured,source:'plugin-settings',credentialSource:'plugin-secret-store'|'existing-token-file'|'existing-local-config'|'none'}, service:{state:'unconfigured'|'stopped'|'starting'|'running'|'retrying'|'error',ready:boolean,manualStop:boolean,pid?,error?,retryCount},login:{state:'idle'|'pending'|'complete'|'error',url?,error?}}`. `running` requires cloudflared's loopback `/ready` success, not just a PID. It proves the connector is connected to Cloudflare, not that the origin, hostname, DNS or KAP public endpoint has been tested; do not claim public Kiki reachability from this state alone.
- `configure {values:{...}}`: allowed settings below; a secret omitted retains it, `null` clears. Return status. Send the chosen `mode`; first-time token mode accepts either a connector token or `tokenFile`. Account credentials, certificate path, public endpoint label and autoStart changes do not restart a connector or clear a temporary pause. The existing-tunnel button can save edited `apiToken`/`accountId`/`certificatePath` through this action, then call `tunnels` in the same user action, even before a connector is configured. A nonempty API token replaces the saved token. Save and connect may take seconds; show inline busy state, poll status while starting/login pending. Failed startup retains configuration and offers Start retry.
- `start {}`: clears temporary pause; starts the existing configuration, independent of `autoStart`.
- `stop {}`: stops owned process and pending retries; sets only `manualStop`, never saves autoStart.
- `login {}`: reuse an existing cert; otherwise begin browser login. Returns promptly. Display `login.url` if opening a browser on the server did not reach the user's machine. The URL is ephemeral and must not be persisted. No second permission dialog: the button itself is the deliberate login action.
- `cancelLogin {}`: stop only the owned login child.
- `tunnels {}`: use API token/account ID when configured, else the existing certificate with official CLI. Return `{items:[{id,name,status?}]}`.
- `accounts {}`: API token required. Return `{items:[{id,name}]}`.
- `selectTunnel {id}`: fetch the existing remotely-managed tunnel's connector token via account API or official CLI, save secret through Host settings and connect in one action. Does not create a tunnel or modify DNS.

Settings: `cloudflaredPath` (optional existing executable), `mode` (`token` default or `local`), `tunnelToken` (secret), `tokenFile` (existing token file, optional), `apiToken` (secret), `accountId`, `tunnelId` (UUID), `certificatePath` (optional, defaults to server user home `.cloudflared/cert.pem`), `configPath` (existing cloudflared config for local mode), `credentialsFile` (optional existing tunnel credentials JSON), `publicUrl` (HTTPS endpoint for the existing Kiki remote-space connection form), `autoStart` (boolean, default true).

Show dependency missing → Install; no configuration → token field plus optional login/reuse route; connected credentials ≠ running service; stopped with autoStart on → Start plus next-start fact; autoStart off → manual Start still works; error → concise reason and retry/configure. Keep advanced certificate/config paths collapsed. Secret inputs are write-only and blank after saving; show configured state, not the saved value.

## Connection settings integration

**Settings → Connection → External connections** manages this service through `createCloudflareConnection` in `@kiki/session-core/settings/externalConnections`. It uses the connected server's existing plugin catalog, install preview, prerequisite installer and sessionless panel backend. An absent catalog entry is not an installable package; installed but disabled offers Enable, an invalid package reports its diagnostics, and a failed lifecycle call stays an error rather than becoming online. The sandbox panel remains available as another consumer of the same handler; no duplicated settings or credentials store is needed.

`publicUrl` is a user-configured endpoint, not a probe result. The typed address helper marks it `reachability:'unverified'`; use the existing Kiki connection flow to retain KAP authentication and identity handshake. Cloudflare transport is not Kiki E2EE and does not replace Kiki's authentication. Keep client authorization and external MCP configuration out of tunnel settings.
