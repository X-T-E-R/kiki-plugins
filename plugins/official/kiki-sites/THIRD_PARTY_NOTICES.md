# Upstream sources and reuse decisions

The Kiki Sites adapter code and routing skill are original MIT work. This package does not redistribute a provider CLI, vendor SDK, dashboard code or third-party skill. It invokes official tools, and its explicit local CLI downloader installs pinned upstream npm packages with their own license files. Provider service terms and account permissions remain separate from software licenses.

## Official tools and APIs used

Verified sources were read on 2026-10-06. CLI flag verification is separate from authenticated deployment: Vercel62.2.0, Netlify27.10.0 and Wrangler4.147.0 were installed with `--ignore-scripts` and their help was executed using an isolated home; all account/deploy success evidence in the automated tests is controlled fixture evidence.

## Mature deployment systems evaluated

| Source | Snapshot evidence | Decision and reason |
| --- | --- | --- |
| [Coolify](https://github.com/coollabsio/coolify), [architecture](https://coolify.io/docs/core/how-coolify-works), [deploy webhooks](https://coolify.io/docs/applications/sources/github/actions) | 62,620 GitHub stars; Apache-2.0. PHP control plane with PostgreSQL/Redis/realtime, SSH to workload servers and Docker/reverse proxy | Defer platform embedding: it introduces server/SSH/container ownership not needed for this local-project-to-managed-target workflow. Official authenticated webhook is a credible future target, but readiness/status was not verified enough to advertise support |
| [Dokploy](https://github.com/Dokploy/dokploy), [architecture](https://docs.dokploy.com/docs/core/architecture), [auto deploy](https://docs.dokploy.com/docs/core/auto-deploy), [official MCP](https://github.com/Dokploy/mcp) | 37,667 stars for main repo. Apache-2.0 outside `/proprietary`; proprietary production/redistribution restrictions under that path. Next.js/PostgreSQL/Traefik/Docker; MCP is Apache-2.0 | Defer dashboard/platform reuse, not a pure-permissive whole-repo donor. Official MCP or `application.deploy` API can later be adapted without rebuilding an orchestrator; current package does not claim it as supported |
| [CapRover](https://github.com/caprover/caprover), [deployment methods](https://caprover.com/docs/deployment-methods), [license](https://raw.githubusercontent.com/caprover/caprover/master/LICENSE) | 15,179 stars; Apache2.0 text plus appended redistribution/paid-feature restrictions, GitHub SPDX `NOASSERTION`. Docker Swarm/nginx/Let's Encrypt control layer | Defer server platform import. Existing-app CLI is plausible, but exact lifecycle/status and license scope need a bounded adapter evaluation before inclusion |
| [GitHub Pages API](https://docs.github.com/en/rest/pages/pages), [GitLab Pages API](https://docs.gitlab.com/api/pages/), [GitLab pipelines](https://docs.gitlab.com/api/pipelines/) | Pages build or CI/pipeline is distinct from repository authentication; actual Pages URL must be read, not constructed | Defer rather than create an unrequested CI engine or claim repository connection equals deployment. Future support should bind an existing Pages build/CI target and observe that deployment, not merely trigger an unrelated pipeline |

Stars are a read-date snapshot, not a stable product attribute. The selected unit of reuse is the production CLI/API itself, not a token donor example or a locally rebuilt cloud engine. That keeps provider auth, upload rules, framework builds and deployment semantics with their upstream owner.
